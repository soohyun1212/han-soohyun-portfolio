# 구현 기준과 결정

## 페이지와 정보 구조

- `/`: Hero → Profile → 집게발(핵심 역량 6개) → 등딱지(대표 프로젝트 3개, 전체 프로젝트 8개) → 꼬리부채(Tool & Skill) → 겹눈(기획 방식) → 더듬이(Contact).
- `/projects/[slug]`: Overview(기본 정보·개요·기여) → Process(4단계) → Decisions(처음 판단·확인한 근거·바꾼 방향) → Result(결과·회고) → 프로젝트 자료 → 이전·목록·다음 이동.
- 프로젝트 분류는 전체 / 신규 서비스 기획 / 서비스 개선입니다. 각 분류에 8 / 4 / 4개를 표시합니다.
- 공통 Sticky GNB는 Projects / About / Contact 앵커 이동을 제공합니다. 상세페이지에서는 Home의 해당 앵커로 이동합니다.
- MEDI-BRIDGE는 첫 프로젝트로 이전 이동이 비활성화되고, 다음은 aqui입니다.

## 디자인 시스템

- 1440px 화면: 최대 콘텐츠 1328px, 좌우 56px 여백.
- 기본 색: Paper `#F8F7F3`, Ink `#20211F`, Coral `#E95D47`, Line `#D7D8D0`.
- 타이포: Pretendard Variable을 로컬 파일로 제공하고 한글·영문·숫자 전체에 공통 적용. 큰 헤드라인·작은 영문 레이블·선으로 정보 위계 구분.
- 대표 프로젝트는 3열, 전체 프로젝트는 4열. 태블릿과 모바일에서는 2열 또는 1열로 조정합니다.
- 둥근 장식 카드 대신 얇은 경계선·여백·번호를 사용합니다. LOBSTER는 코드로 작성한 단색 SVG 그래픽입니다.
- 스크롤 앵커와 절제된 hover/motion을 적용하고, reduced-motion 환경에서는 애니메이션을 끕니다.

- 하나투어 기간: 전체 목록에는 2026.09.03 시작, 서비스 개선 필터와 상세 Overview에는 2026.09.10 시작으로 기재되어 있습니다. 상세 Overview 22페이지의 **2026.09.10–2026.12.10**를 사용했습니다.

- 기획 역량은 최종 IA 및 화면설계서의 6개 구분을 사용했습니다.

## 콘텐츠 출처

`src/data/projects.json`의 sourcePages는 화면설계서 PDF의 1부터 시작하는 실제 페이지 번호입니다.

| 프로젝트 | 화면설계서 페이지 |
| --- | --- |
| MEDI-BRIDGE | 14–17 |
| aqui | 18–21 |
| 하나투어 | 22–25 |
| 제주형 응급의료 | 26–29 |
| Weverse | 30–33 |
| MOMOA | 34–37 |
| 쿠팡 로켓프레시 | 38–41 |
| 계원예술대학교 | 42–45 |

프로젝트 데이터는 화면설계서의 실제 방문자용 영역을 추출하고 줄바꿈만 정리했습니다. 화면 설명용 번호·주석은 콘텐츠에 넣지 않았습니다. 프로젝트 이미지와 프로필 사진, 이력서·프로젝트 산출물 원본은 사용자 요청대로 비워두었습니다.

## 실행과 배포

Next.js App Router, TypeScript strict, Tailwind CSS 4를 사용합니다. Vercel 표준 Next.js 빌드로 배포할 수 있으며, 특정 PC의 절대 경로를 앱 코드에서 참조하지 않습니다. 개발 서버는 이 PC에서만 접근하도록 127.0.0.1:3000에 바인딩합니다. 외부 공개 배포는 수행하지 않았습니다.
