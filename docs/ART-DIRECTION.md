# MONOCHROME HALFTONE EDITORIAL

## 진단과 적용

이전 버전은 추상 SVG 가재와 컬러별 프로젝트 커버를 사용해 실제 사진의 명암·질감이라는 TYPE 3 기준과 차이가 있었다. 이번에는 사진, 큰 압축 영문 활자, 열린 그리드, 얇은 구분선을 주된 시스템으로 삼았다. 기존 IA와 프로젝트 내용은 유지했다.

- 최우선 첨부 레퍼런스 TYPE 3: 실사 질감과 밝기에 따라 면적이 변하는 미세 망점. 카드 형태와 SIM 칩은 차용하지 않았다.
- [Halftone Studio](https://remarkable-sunflower-364319.framer.app/): 흑백 사진과 크게 배치한 활자의 대비를 참고했다.
- [Halftone Lite](https://yummy-walkthroughs-727876.framer.app/): 큰 작업 이미지와 그 아래 제목·설명을 두는 편집 방식을 참고했다.
- [Obys](https://obys.agency/): 큰 영문 제목, 이미지와 작은 메타데이터의 크기 대비, 넓은 여백을 참고했다.
- [Pierre Rousseau](https://pierrerousseau.info/): 실제 페이지는 열었지만 검수 환경에서 스타일이 적용되지 않았다. 의도된 그리드를 확인했다고 간주하지 않았다.

## 디자인 시스템

색상은 #111111, #F5F5F2, #B8B8B8, #E0E0E0, #EF4540. 밝은 Hero·Profile·Projects, 어두운 핵심 역량·Contact, 회색 Tool 영역으로 리듬을 만든다. 코럴은 슬로건과 작은 포인트에 제한한다.

기본 글꼴은 한글·영문·메타데이터 모두 Pretendard로 통일한다. 맨 위 LOBSTER 제목과 겹눈 섹션의 큰 숫자에만 기존 Oswald를 유지한다. 상세페이지 진행 과정 숫자도 Pretendard를 사용한다. 두 글꼴 모두 로컬 파일로 제공하며 IBM Plex Mono는 로드하지 않는다. 데스크톱 콘텐츠 최대 폭은 1344px이며 1440px 화면에서 좌우 48px 여백을 둔다.

Hero는 큰 LOBSTER 제목 아래 설명과 실제 사진을 비대칭으로 배치한다. FIG.01 캡션과 기획 과정은 독립된 영역이다. 내비게이션에는 섹션과 혼동되는 번호를 쓰지 않는다.

프로필 사진 2개, 대표 프로젝트 3개, 전체 프로젝트 8개와 상세페이지 이미지는 공통 `ImagePlaceholder`로 구성한다. 단색 #E0E0E0이며 내부 텍스트·패턴·장식·그림자가 없다. 프로젝트 카드 이미지는 4:3이다. 실제 이미지 교체 전 임의 커버를 표시하지 않는다.

핵심 역량 6개와 기획 방식 3개는 번호/제목/본문 위계를 통일한다. 프로젝트 상세는 Overview / Process / Decisions / Result / Project Deliverables를 유지한다. aqui의 제품명은 NFC 디바이스로 바로잡았다. 이메일과 전화번호는 독립된 행/열로 구분한다.

## 파일 연결 확인

이력서와 프로젝트 산출물은 공통 다운로드 버튼으로 표시한다. 실제 파일을 받기 전에는 비활성 상태이며 메일 요청 링크를 사용하지 않는다. 검토된 이력서 파일 경로는 `src/data/documents.ts`, 산출물 파일 경로는 각 프로젝트의 `downloads`에 연결한다.

## 검수

Next.js 프로덕션 빌드 및 TypeScript 검사 통과. 별도 Chrome 헤드리스 브라우저에서 홈/상세 1440·1024·768·390·360px 가로 넘침, 프로젝트 필터 8/4/4, 상세 8개, 알 수 없는 경로 404, 목록 복귀, 전화번호 복사와 메일 링크를 검수했다. 사용자 컴퓨터 설정이나 개인 브라우저 프로필은 조작하지 않았다.
